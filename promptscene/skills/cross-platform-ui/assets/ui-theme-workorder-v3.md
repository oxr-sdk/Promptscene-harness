## F0 — "흰 유리"의 정체 (이게 이번 판의 핵심 지식)

참조 이미지(iOS 제어센터)의 실제 스택은 이렇다:

```
배경(월페이퍼) → ① dim(어둡게) → ② blur → ③ 흰 film α.15~.25 → ④ 밝은 rim → ⑤ 흰 아이콘
```

**놓치기 쉬운 건 ①이다.** iOS는 유리를 얹기 전에 배경을 어둡게 만든다. 그래서 흰 film이 "밝은 유리"로 보이면서도 흰 아이콘이 읽힌다. ①을 빼고 밝은 배경 위에 흰 film만 얹으면 대비가 죽는다.

**대비 계산으로 확인 (밝은 하늘 L≈0.75 가정):**

| 스택 | 배경 휘도 | 흰 텍스트 대비 |
|---|---|---|
| 흰 film α.18 직접 | 0.51 | **1.9 : 1** ❌ |
| 어두운 scrim α.55 → 흰 film α.14 | 0.15 | **5.2 : 1** ✅ |

**결론 — 흰 유리는 "패널"이 아니라 "컨트롤"에 쓴다:**
- **Panel = Scrim** (어두운 `rgba(10,13,18,.55)`) ← iOS의 dim 역할. 대비는 전부 여기서 나온다.
- **IconButton = Film** (흰 `rgba(255,255,255,.14)` + rim `α.22`, 상단 `α.40`) ← iOS의 light glass 역할. **이미 어두워진 패널 위**에 얹히므로 흰 글리프가 읽힌다.
- ON 상태 = `Accent` 채움 + **어두운 글리프**(`#0A0D12`).

목업의 "밝은 창가" 배경으로 바꿔보면 이 이유가 눈으로 보인다. 이건 취향이 아니라 산술이다.

### 토큰 변경
```
Scrim      rgba(10,13,18,.55)   ← PanelTint 대체(이름도 역할로 바꾼다)
Film       rgba(255,255,255,.14)
FilmHover  rgba(255,255,255,.22)
Rim        rgba(255,255,255,.22)
RimLit     rgba(255,255,255,.40)
OnGlyph    #0A0D12
Card       삭제 — F1의 아이콘 그리드가 컨테이너를 없앤다
```

## F1 — 블러: 지금 넣지 않는다 (근거가 강해졌다)

정찰 결과, VR에서 **에디터에서는 되고 실기기에서는 안 되는** 전례가 확인됐다(URP Kawase blur Renderer Feature를 Quest에서 못 돌린 사례). 스테레오 렌더 경로에서 스크린스페이스 샘플링이 깨지는 계열의 문제이고, 이건 우리가 겪으면 원인 규명에만 한 세션을 태울 종류다.

**F0의 scrim + film + rim이 블러 없이 그 인상의 대부분을 만든다.** 블러의 지각적 역할은 (a) 배경 디테일 숨기기 (b) 깊이 분리인데, scrim이 (a)를 거의, (b)를 완전히 해낸다.

**개척 청구서 항목으로 기입** — 착수 시 경로 3개와 비용:
1. URP Renderer Feature(Kawase/Dual-filter) + `_CameraOpaqueTexture` — **실기기 실패 전례 있음**, 스테레오 UV 처리 필수
2. 전용 카메라 + 저해상도 RenderTexture를 패널 뒤에만 렌더 후 블러, 저빈도 갱신 — 패널 1장이면 현실적
3. 정적 블러 배경(한 번 굽기) — 환경이 안 변하는 룸에서만

**착수 게이트: Quest 실기기 프레임 예산 실측 없이는 머지 금지.**

## F2 — IconButton 원형 그리드 (사용자 요청 ②)

행(Row)을 버리고 **원형 아이콘 버튼 그리드**로 간다. 부수 효과가 크다: 카드 컨테이너가 사라지므로 v2 D2의 "중첩 깊이 ≤1"이 자동 만족되고, 본문 텍스트가 유리 위에서 사라지므로 F0의 대비 문제도 같이 없어진다.

- 원 지름 `120px` = 0.10 m = **3.8°** (탭 타깃 하한 1.5°의 2.5배)
- 글리프 `48px`, 라벨은 원 **밖 아래** `FontFoot(16px)` / `TextLo`
- ON = `Accent` 채움 + `OnGlyph`, 라벨 `TextHi`+`WeightEmph`
- hover = `FilmHover` (레이 포인팅의 조준 피드백 — 장식 아님)
- 그리드 = 가로 flex + wrap, gap `Space4`. 720px 패널에 4개/행

### ⭐ `ContentMeta.Icon`이 드디어 소비자를 얻는다
계약 §2의 `ContentMeta`에는 처음부터 `public Sprite Icon;`이 있었고 아무도 안 썼다. 이 그리드가 그 필드의 첫 소비자다. **계약 변경 0.**

폴백 체인 (모두 런타임, 직렬 필드 0):
1. `Meta.Icon != null` → 스프라이트
2. 아이콘 폰트 코드포인트 매핑이 있으면 → 글리프
3. 둘 다 없으면 → `DisplayName` 첫 글자

> **범위 주의:** 이건 사실상 Phase 3 런치패드의 "아이콘 그리드"다. 회고의 질문("룸마다 UI 컨셉이 다를 텐데 아이콘 그리드가 맞나?")에 대한 답은 **"토글 도구 HUD에는 맞다"**로 한정한다. 런치패드 스코프 전체를 되살리는 게 아니다 — HUD의 모양이 그리드가 된 것뿐이며, 이 한정을 SKILL.md 정직 계약에 적는다.

## F3 — 아이콘 = 폰트로 (스프라이트 파이프라인 회피)

**Material Symbols**: 2,500개 이상의 아이콘이 **단일 폰트 파일**에 들어 있고 **Apache License 2.0**이다. 스프라이트를 만들면 Addressables/baked 경계 결정이 따라오는데, 폰트는 **파일 하나**라 그 질문이 안 생긴다. D3(에셋 공장) 착수 없이 아이콘이 해결된다.

**함정 (반드시 지킬 것):**
- **가변 폰트(variable font) ttf를 쓰지 말 것.** Unity는 가변 축을 조절하지 못하고, 가변 ttf에서 TMP 아틀라스를 굽자 특정 코드포인트가 없는 것으로 보고된 사례가 있다. **정적(static) 인스턴스**(예: Outlined Regular)를 받아 쓴다.
- **Unity는 리가처를 지원하지 않는다.** 목업은 `chat` 같은 리가처 이름으로 그렸지만, Unity에서는 **코드포인트**를 Material Symbols 사전에서 찾아 `\uXXXX`로 넣어야 한다.
- 필요한 아이콘만 서브셋하면 파일이 아주 작아진다. 지금 필요한 리가처 이름: `chat` / `chair` / `straighten` / `back_hand`. (과녁·점수는 추가 시 결정)
- **아틀라스를 굽고 나서 각 코드포인트가 실제로 존재하는지 검증**하고, 없으면 정지·보고(폴백 글자로 조용히 넘어가지 말 것 — 그러면 왜 아이콘이 안 나오는지 영원히 모른다).
- 아이콘 폰트 FontAsset도 **baked base**에 둔다(본문 폰트와 동일 이유).

## F4 — KeyBadge: 월드 상호작용 프롬프트 (사용자 요청 ③ + 결함)

캡처의 `"E 키로 앉기"`는 바닥을 가로지르는 2 m급 텍스트다. **결함 두 개가 겹쳐 있다:**
1. 월드 텍스트에 크기 규율이 없다 — 월드 스케일 고정이라 보는 위치에 따라 벽만큼 커진다
2. 그게 HUD 컴포넌트가 아니라 **다이제틱 프롬프트**인데 디자인 시스템 밖에 있었다

**신규 컴포넌트 ⑥ `KeyBadge`** — 원형 유리 배지(`Film` + `RimLit` 2px) 안에 키캡 글자.

**핵심 기계 = 각크기 고정.** 거리와 무관하게 항상 같은 시야각을 차지하게 만든다:

```csharp
// 목표 각크기 targetDeg(기본 3°)를 유지
float dist  = Vector3.Distance(cam.position, transform.position);
float worldD = 2f * dist * Mathf.Tan(0.5f * targetDeg * Mathf.Deg2Rad);
transform.localScale = Vector3.one * (worldD / baseDiameterMeters);
transform.rotation = Quaternion.LookRotation(transform.position - cam.position); // 빌보드
```
2 m에서 3° → 지름 약 0.105 m. 폭주가 구조적으로 불가능해진다.

**표시 규율:**
- 상호작용 대상 **위쪽에 오프셋** 배치(바닥에 눕히지 않는다)
- 원거리 = 배지만(`E`). **근거리(~2 m 이내)** = 배지 + 라벨(`앉기`)을 Scrim 알약에 담아 옆에
- 라벨은 `FontFoot`, 배지 글자는 `WeightEmph`

`HudTheme`에 추가: `BadgeTargetDeg = 3f`, `BadgeLabelDistanceM = 2f`.

## F5 — 게이트 갱신

**U6 (타입)** — 변경 없음. 단 배지 글자·아이콘 글리프는 램프 밖 크기이므로 **역할 예외로 명시 등록**(임의 예외 금지, 화이트리스트).
**U7 (대비)** — **F0 산술을 코드로.** 각 텍스트/글리프에 대해 조상 스택의 합성 휘도를 계산하고, **최악 배경(흰색·검정 양쪽)** 가정에서 대비 ≥ 4.5(본문) / ≥ 3.0(48px 이상 글리프)를 단정. 흰 `Film`이 **Scrim 없이** 환경에 직접 노출된 노드가 있으면 **FAIL**.
**U9 (구성)** — 컴포넌트 6종으로 갱신(Title / IconGrid / IconButton / Footnote / ActionRow / KeyBadge). `Card` 사용 0건. 미분류 0건.
**U10 (신설, 각크기 폭주 방지)** — 씬의 모든 월드 텍스트/배지가 각크기 고정 컴포넌트를 갖거나 화이트리스트에 있어야 한다. 고정 없는 월드 텍스트 = **FAIL**. (`"E 키로 앉기"`가 통과했던 구멍을 닫는다.)
**U11 (신설, 아이콘)** — `Meta.Icon`/코드포인트/첫글자 폴백 체인이 결정적으로 동작하고, 사용된 코드포인트가 아틀라스에 **전부 존재**함.
**U8 (캡처)** — 유지, 판정 아님. 이번 방향 전환을 촉발한 게 캡처다.

- 코드포인트가 아틀라스에 없으면 → 폴백으로 조용히 넘기지 말고 정지·보고
